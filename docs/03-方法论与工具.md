# 方法论与工具

这份文档记录本仓库用到的判定顺序和工具，目的是让别人拿到一个新的 VPN APK 时，
能在半小时内判断「值不值得投入」，而不是一头扎进反编译。

## 1. 十分钟判路线

拿到 APK 先看三样，不看代码：

```bash
python -I tools/dex_strings.py app.apk out.txt          # 字符串池
python -I tools/axml.py app.apk                          # manifest：包名、版本、服务
python -I tools/elf_jni.py app.apk                       # 每个 .so 的 Java_* 导出
```

判据表：

| 信号 | 结论 | 后续成本 |
|---|---|---|
| dex 里有 `ss://` `vless://` `vmess://` 字面量 | 节点内嵌 | 分钟级，直接抠 |
| 有 `getAllServers` / `getNewServers` 这类方法名 + 一个域名 | 接口直吐订阅 | 小时级，本轮就能落地 |
| 只有 `libbox.so`（sing-box）或 `libv2ray.so` | 标准协议，但节点仍要下发 | 取决于下发方式 |
| 私有 `.so`（`libnms.so` / `libsswanutils.so` / `libtlsvpn.so`） | 自研协议 | 天级起步 |
| 字符串池里只有广告 SDK 域名 | 业务主机在运行时构造或加密 | 需要动态 |

**先判再挖。** 本批四个样本在第三步就全军覆没：字符串池里除了广告 SDK，一个业务域名都没有。

## 2. jadx 卡死时的替代路线

jadx 1.5.1 在部分大 APK 上会卡死在 `Resetting disk code cache` 之后——换线程数、
换 JDK 17/25、堆调到 16g 都复现，CPU 计数不涨。不要在这上面耗时间。

替代方案是 androguard 逐 dex 定向反汇编：

```bash
python -I tools/dex_classes.py app.apk '^Lcom/vendor/'      # 枚举包内类
python -I tools/dex_disasm_class.py app.apk 'com/vendor/Foo' # 单类字节码
python -I tools/dex_xref_class.py app.apk 'bean/InitResponse' # 谁引用了这个类
```

三个脚本都是秒级（单个 dex 解析 <1s），比等 jadx 靠谱。

配合 `tools/dex_ref.py` 做 const-string 反查：给定字符串（比如一个域名），
直接定位到引用它的类和方法。

## 3. ELF 分析四件套

```bash
python -I tools/elf_jni.py      app.apk          # 导出的 Java_* 符号
python -I tools/elf_disasm.py   lib.so 0x1afb0 400   # 指定地址反汇编
python -I tools/elf_xref.py     lib.so "字符串A|字符串B"  # adrp+add 字符串交叉引用
python -I tools/elf_pltmap.py   lib.so           # PLT 槽 → 导入符号
python -I tools/elf_va2off.py   lib.so 0x931d0   # vaddr ↔ 文件偏移
```

`elf_xref.py` 是最有用的一件：白标 App 的 native 层经常把算法名、类名、常量串
明文放在 `.rodata`，一条 `adrp + add` 就能定位到调用点，比从头读汇编快一个量级。

`elf_va2off.py` 别省：`.so` 里 `.text` 以外的段 vaddr 和文件偏移通常差一个
page 对齐值（本批遇到 0x1000 和 0x8000 两种），算错了读出来的全是不相干的数据。

## 4. JNI 注册表恢复

没有 `Java_*` 导出、native 方法全是 `code=False` 时，走 `RegisterNatives`。
在 `JNI_OnLoad` 里找 `blr` 到 `[env+0x6b8]` 的调用，三个参数分别是：
clazz、`JNINativeMethod*` 表、条目数。

表里有三根指针：`name` / `signature` / `fnPtr`。

- `fnPtr` 一般是 `R_AARCH64_RELATIVE`，取 relocation 的 `addend` 就能换成符号名。
- `name` / `signature` 通常也是 RELATIVE，但目标是 `.rodata` 里的字符串而不是符号，
  要自己按段映射把地址读成 C 字符串。

本仓库的 `elf_pltmap.py` + `elf_va2off.py` 组合能覆盖这一步。

## 5. 五种节点来源形态

按「能不能静态拿到」排序：

1. **dex 直写字面量** —— 抠出来即可。
2. **接口直吐订阅** —— 复刻请求即可（FastVPN、EdgeVPN 那一类）。
3. **静态加密资产** —— 找到解密函数即可（本仓库 `asset_decrypt_easyvpn.py` 就是这类）。
4. **运行时构造的接口 + 常量密钥** —— 密钥能静态抠，主机名要动态（本批 `com.vpnmasterx.fast`）。
5. **账号态下发 / 签名门禁 / 设备绑定** —— 静态到头，必须动态（本批其余三个）。

判断自己在第几层，比埋头挖多久都重要。

## 6. 判死的三个信号

- 字符串池里除了广告 SDK 没有任何业务域名 → 主机名是运行时拼的，静态没戏。
- native 解密函数开头有 `cmp wXX, #0x????` 之类的魔数比较 → 签名/设备指纹门禁，
  过不了就直接返回 null。
- `.so` 里同时出现自研 `AES::EncryptBlock` 和 `Xor` → 不是标准 JCE，复刻要读轮密钥编排。
